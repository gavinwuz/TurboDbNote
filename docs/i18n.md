# 多语言语义键规范

## 方案与文件

采用扁平 JSON `strings` 字典和稳定英文语义键。中文原文键容易随文案修改失效，数字编号不便阅读，英文原文键仍绑定展示文字；语义键兼顾稳定性与可读性，不引入额外翻译框架。

- `crates/desktop/assets/locales/en.json`：内置英文，也是最终回退语言。
- `crates/desktop/assets/locales/zh-CN.json`：内置简体中文，与英文拥有相同键集合。
- `crates/desktop/assets/locales/legacy-keys.json`：旧中文/英文原文键到新键的兼容映射，不是语言包。
- `src/locale_catalog.rs`：构建与运行时共用的解析、校验和占位符实现。
- `src/locale.rs`：加载外部包、选择语言、回退和界面调用。

```json
{
  "schema_version": 2,
  "id": "zh-CN",
  "name": "简体中文",
  "strings": {
    "panel.inspector.title": "检查器",
    "chat.models.loaded": "已加载 {count} 个模型"
  }
}
```

`schema_version` 是语言包格式版本，不随普通文案修改增长。省略时按旧版 1 处理；目前支持版本 1 和 2。`id` 为语言标识，`name` 为语言自身的显示名称。点号只用于组织名称，字典不嵌套。

## 命名规则

- 小写英文，以点号区分模块和语义，单段内可用下划线。例如 `settings.autosave.error`。
- 用途明确：`title`、`label`、`tooltip`、`description`、`empty`、`error` 等。
- 同一含义的小改文案保留原键；含义改变或语境不同则创建新键。
- 不把原文整句、数字序号、文件路径、数据库名或外部报错作为键。
- “连接”按语境分开：`navigation.connections` → Connections；`chat.context.connection` → Connection；`agents.action.connect` → Connect。
- 仅复用语境和含义一致的通用键，避免为了减少条目而过度合并。

## 代码调用

```rust
let title = crate::locale::t(cx, "panel.inspector.title");
let text = crate::locale::tr(
    cx,
    "chat.models.loaded",
    &[("count", &models.len().to_string())],
);
```

`tr` 使用完整句子和命名参数，允许不同语言调整词序。不在翻译外拼接“已加载”＋数量＋“个模型”。参数中出现花括号不会被二次展开，`{{` 与 `}}` 表示文案中的字面花括号。参数缺少、多余或重复都会校验失败。

`message(cx, value)` 用于已有状态字段：只把已知语义键翻译，其余文本原样显示。外部服务报错不会通过旧原文键映射翻译，也不会因为包含 `{...}` 就被当模板解析。诊断日志和历史提示在产生时格式化，已经产生的日志不追溯翻译；界面静态标签和输入提示会随语言切换刷新。用户笔记和模型回答内容不翻译。

当前模板仅支持命名插值，不声称支持 ICU 复数、性别变体和地区数字格式；需要这些功能时再升级模板方案，并提高兼容性测试覆盖。

## 外部包与回退

将外部包放到 `settings.db` 同目录的 `locales/`，重启后在通用设置选择。允许只提供部分键。

回退顺序：当前外部覆盖 → 当前语言内置值（如存在）→ **内置英文值**。外部英文覆盖不会改写其它语言的最终英文基准。未知语言也回退内置英文。

外部文件按文件名排序读取；同一语言的后续文件覆盖前面的同名键。重复 JSON 键、格式错误、空译文、占位符不匹配、超过 1 MiB 或不支持的格式版本会拒绝该文件，保留可用内置语言。未知条目忽略，方便较新语言包在较旧应用中继续使用已支持部分。

缺失的程序引用在开发构建中输出诊断；最终找不到文案时显示通用英文提示，不直接将 `panel.xxx.title` 暴露在产品界面。

## 一版旧键兼容

以下旧包仍可覆盖检查器名称：
```json
{"id":"zh-CN","name":"简体中文","strings":{"检查器":"我的检查器"}}
```
加载时按 `legacy-keys.json` 转换。若同一文件同时提供旧键和新语义键，**语义键优先**。历史“属性”“数据库结构”等键也映射到相应稳定标识。兼容表保留本次格式迁移期，后续移除必须另行声明；新代码和新语言包只写语义键。

## 构建验证

`cargo check/build/test` 自动运行语言包校验：
1. 重复键、空文案、非法命名、语言元数据。
2. 中英文键集合和命名占位符一致。
3. 旧键映射目标真实存在。
4. Rust 源码中静态可识别的语义键、直接 `t/tr` 引用及 `tr` 参数符合字典。

动态变量通过 helper 传递时，以运行时校验和测试补充。不要在运行时拼装键名。日常改文案只编辑对应语言包，不改 Rust 调用；新增条目同时补齐中英文。

回归测试覆盖：部分外部包回退、旧键覆盖、语义键优先、重复键、占位符错误和参数不二次展开。
